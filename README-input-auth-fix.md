# TyperX — исправления ввода и авторизации (typing-auth-1)

## Что подтверждено по исходникам

1. SmartSplitter в исходном backend считает «Привет» самостоятельной смысловой
   границей. Поэтому настройка «3 слова» не означала ровно 3 слова.
2. TypingService допускает перекрытие удерживаемых клавиш, а модификатор Shift
   отпускается вместе с первой буквой. На высокой скорости следующая буква
   может быть нажата до отпускания Shift — что согласуется с «ПРивет».
3. Ошибки Telegram и драйвера слишком обобщены. Один ValueError не позволяет
   подтвердить конкретную причину сбоя входа пользователя.

## Что изменено

- Desktop output теперь делит нормализованный текст строго по N словам.
  Не выделяет приветствия и вопросительные слова в отдельные сообщения.
- Клавиши нажимаются последовательно: key-up и отпускание модификаторов
  завершаются до следующего key-down. Искусственные опечатки отключены.
- Поддержка 25–300 WPM сохранена как целевой темп, не гарантия измеренной
  скорости. Проверки, драйвер, UIA и пауза после Enter добавляют задержку.
- Все символы проверяются до первой печати. Caps Lock, зажатые модификаторы
  и комбинации Ctrl/Alt для неподдерживаемых символов блокируют запуск.
- Cleanup отслеживает даже частично выполненный key-down. F9, потеря фокуса
  и ошибки удержания не блокируют попытку key-up. При отказе самого драйвера
  гарантировать отпускание физической клавиши программно невозможно.
- F9, проверка HWND/PID, документа/чата и поля сохранены. Нормализуются только
  известные безвредные изменения: * у проверенного Notepad и счётчик
  непрочитанных у Telegram. Для ручного режима это делается только при
  доступном UIA ID поля; иначе остаётся исходная строгая проверка.
- В ручном Telegram-режиме для проверенного UIA поля требуется отдельное окно
  чата, а не общее окно с заголовком Telegram. Поле должно быть пустым.
- Вход проверяет сохранённые API ID/hash, международный телефон, порядок
  запроса кода и 2FA. Пароль не обрезается: пробелы могут быть значимыми.
- Пустой код не превращается в скрытый повторный send_code_request. Успех
  sign_in сам по себе не считается авторизацией: проверяется состояние клиента.
- Неподтверждённый logout не отображается как успешный. Ошибка подключения
  не удаляет session, ключи и настройки и не отзывает аккаунт автоматически.
- Необъяснённая ошибка получает безопасный код TG:<операция>:<тип>:<место>
  без exception message, паролей, телефона, токенов, текстов чата и локальных
  переменных. Именно этот код можно прислать для дальнейшего разбора.

## Установка

1. Нажать F9 и закрыть окно TyperX. Остановить `npm run desktop:dev` через Ctrl+C.
   Во время пересборки старый engine не должен работать.
2. Распаковать архив в существующий корень TyperX-desktop с заменой файлов.
   Нужные новые файлы находятся в bridge/typerx_desktop/; одного обновления
   __main__.py недостаточно.
3. Не удалять .venv, backend, Cargo.lock, package-lock.json, requirements.lock,
   ai.json, ai-secrets.bin или telegram.session. Архив не меняет версии
   зависимостей и не заменяет настройки аккаунта.
4. Из корня выполнить по очереди:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_input_auth_fix.py" -v
.\scripts\build-engine.ps1
npm run desktop:dev
```

Переходить к следующему шагу только после успеха предыдущего. Пересборка
обязательна: Tauri запускает упакованный exe, а не изменённые .py напрямую.
После подключения нового движка до запуска в detail отображается маркер
`typing-auth-1`. Если маркера нет — запущен прежний exe.

## Проверка ввода

Сначала пустой локальный тестовый документ, не настоящий разговор.
Caps Lock выключен, Shift/Ctrl/Alt/Win отпущены. Параметры: 300 WPM, 3 слова.
Подтверждение Enter и F8 остаются обязательными.

Ожидаемая последовательность для «Привет Привет Привет как дела?»:

```text
Привет Привет Привет [Enter]
как дела? [Enter]
```

Enter в Telegram может отправлять сообщения. Уже отправленное не отменяется.
Проверить F9 во время первой буквы: после остановки не должен отправляться
незавершённый фрагмент и не должен оставаться зажатый Shift.
Проверить смену поля/окна: ввод должен остановиться. Автовозобновления нет.

## Проверка Telegram

Сохранить телефон с +кодом страны. Запросить новый код, ввести код, затем
пароль 2FA только при запросе. При повторной ошибке прислать строку [TG:...],
но не пароль, код входа, API hash, API key или файл сессии.

Конкретный ValueError на компьютере пользователя пока не воспроизведён.
Этот patch исправляет проверенные проблемы потока авторизации и делает
неизвестный остаточный сбой диагностируемым, а не обещает исправление любой
возможной ошибки Telegram, драйвера или Windows.

## Проверено здесь

41 unit-тест на подставных драйвере, времени, Telegram-клиенте и части
Windows API; Python compileall. Проверены точное разбиение, последовательность
press/release, отмена, отсутствие Enter после незавершённого фрагмента,
проверка всего текста до печати, очистка частичного key-down, код/2FA,
просроченный код, подтверждение авторизации и отсутствие секретов в ошибках.
Результат приложен в test-results.txt.

Реальные Windows UIA/Interception/Telegram, сеть и сборка PyInstaller в этой
среде недоступны. Поэтому нельзя утверждать, что «все баги» приложения устранены.
